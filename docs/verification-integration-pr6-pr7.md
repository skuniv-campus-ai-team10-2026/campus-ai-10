## 2. 발견 사항

### 2-1. PR #6만 먼저 적용된 DB에서는 통합 서버가 시작되지 않음 (재현)

1. 빈 DB에서 PR #6 jar 실행 → Flyway 기록 V1~V7, V9
2. 같은 DB에서 통합 jar 실행
- 기대: V8 적용 후 시작 / 실제: `Detected resolved migration not applied to database: 8.`로 시작 실패
- 원인: Flyway 기본 설정은 순서가 뒤바뀐 마이그레이션을 허용하지 않는다.
- **결론(2026-10-27 조장 확인)**: 공유 DB는 V7까지라 해당 없음. V8·V9 번호를 유지하고 **#7 → #6 순서로 병합한 뒤 통합본으로 배포**한다. PR #6 단독 버전을 실제 DB에 띄우지 않는다.

### 2-2. 정산되지 못한 예약이 계속 남음 (한계, 운영 개선 항목)

- 테스트: 공급자 응답 성공 후 정산 UPDATE 실패 → 예약 1,203 micro-USD가 `reserved`로 남고 이후 호출로도 해제되지 않음
- 실제 프로세스: 응답 대기 중(가짜 공급자 20초 지연) 강제 종료 → 재시작 후 호출 수 1회 포함, `reservedUsd = 0.00147` 잔류
- 과다 집계라 비용 초과 위험은 없지만 한도가 일찍 닫힐 수 있다. 시연 영향과 확인 방법은 [routing-and-budget.md](routing-and-budget.md)의 "시연 중 한도에 일찍 닿을 수 있는 경우"에 적었다. 실제 사용량 확인 없이 예약액·누적 사용량을 지우지 않는다.

**계정 × 기존 기능**: 1절 표의 `IntegrationAccountFlowTest`. 잘못된 현재 비밀번호 400·로그인 유지는 PR #6 기존 테스트로 확인. **회원가입·프로필 화면은 PR에 없어 UI 미검증.**

**부서 매칭**: 시연 배정 켜짐에서만 냉난방·정수기 시연용 배정, 확인됨 경로로 표시하지 않고 연락처 미노출. 정수기/천장 누수 구분은 DEMO 키워드 분류로만 확인(실제 LLM 정확도 아님). 미배정 사유 4종이 실제 상태와 일치. 실제 프로세스 4회 시작 후 유형별 규칙 1개씩. 관리자 수정 규칙 보존(PR #7 테스트). 기존 WIFI·전기·누수·학사, 부서 권한 기존 테스트 PASS.

**사용량 제한**
- LLM·Embedding 각 경계에서 차단, 동시 10요청 중 한도 수만 공급자 도달
- 새 계정 3개 × 재로그인 × 새 접수 UUID로도 서비스 전체 한도(4회)에서 정지
- 실제 프로세스 강제 종료 후 재시작해도 누적 사용량·차단 유지, 공급자 호출 수 그대로
- DAILY: 서울 날짜 키(JVM 시간대 무관), 어제 행이 꽉 차도 오늘은 새로 시작. 실제 자정 경과는 미검증
- 시간 초과·500: 재시도 없이 1회, 예약액이 사용액으로 기록. 사용량 누락: 0이 아니라 예약액. 예약 DB 실패: 공급자 호출 0
- 한도 초과 후 검토 접수·직접 접수·기존 신고 조회·관리자 처리 가능(유료 호출 없음)
- 사용량 조회: 총괄 200, 부서 담당자·학생 403, 비로그인 401
- 예약 크기: 예약 = 실제 전송 요청 크기 × 입력 요율 + 설정된 출력 상한(`AI_MAX_COMPLETION_TOKENS`) × 출력 요율. 분석 요청 약 7.2KB에서 출력 상한 1,000이면 약 1,203, 기본 1,536이면 약 1,470 micro-USD. 이전 실제 측정 평균 약 260 micro-USD의 4~6배. 추가 질문이 붙는 접수(hybrid) 요청은 따로 재지 않음

### 실제 과금 상한을 보장하지 못하는 조건

1. 설정 요율(`AI_PRICE_*`)이 실제 모델·서비스 티어 요금과 다를 때(호출 수 상한은 유효)
2. 토큰 수가 글자 수보다 많을 때: 입력 예약은 글자 수 기준이다. 한글이 매우 긴 Embedding 입력(최대 12,000자)은 초과 가능하며, 동시 진행 호출 수만큼 상한을 조금 넘을 수 있다
3. 같은 키를 앱 밖(평가 스크립트, 다른 DB를 쓰는 다른 배포본)에서 쓸 때. 평가 테스트는 `complete()`를 직접 호출해 예산을 거치지 않는다
4. 서버 계산은 추정이다. 실제 청구 상한은 OpenAI 프로젝트 사용 한도로만 보장된다(배포 전 설정 예정)
