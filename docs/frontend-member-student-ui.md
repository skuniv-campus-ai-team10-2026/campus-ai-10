# 회원 기능 및 학생 화면 변경

기준: `8e46408`을 포함하는 `main`, 작업 브랜치 `feat/member-student-ui`.

## 구현

- `/signup`: 회원가입, 아이디·이름·비밀번호·확인 검증, 가입 성공 후 로그인 이동.
- `/profile`: 아이디·역할·부서 읽기 전용, 이름 변경과 공통 상태 갱신, 비밀번호 변경.
- 비밀번호 변경 성공 시 세션 상태, CSRF 캐시, 접수 초안, 마지막 접수번호, 메모리의 사진을 정리한다. 추가 로그아웃 요청은 하지 않는다.
- 학생 메뉴·목록·뒤로가기·완료 버튼은 접수내역으로 통일한다. 관리자 소속 안내는 유지한다.
- 사진 선택 안내를 정리하고 검증·드롭·미리보기·조회·삭제를 유지한다.
- 완료 화면에서는 사진 영역을 표시하지 않는다. 별도 `AutoUploadPhotos`가 기존 공유 업로드 상태와 중복 방지를 사용한다.

## Mock 및 실제 API 구분

기본값은 실제 API 모드다. 기존 `api`, `post`, `patch`를 사용하며 `/api`를 제외한 계약 경로로 요청한다. 실제 모드의 쿠키·CSRF 흐름은 유지한다. API 요청 코드 연결과 실제 서버 통합 검증은 구분한다.

회원 Mock을 사용하려면 `frontend/.env.local`에 다음을 넣고 개발 서버를 재시작한다.

```dotenv
VITE_ACCOUNT_MOCK=true
```

Mock은 회원가입·로그인·내 정보·이름 수정·비밀번호 변경·로그아웃만 메모리에서 처리한다. 먼저 회원가입한 계정으로 로그인한다. 중복 아이디와 현재 비밀번호 불일치 오류를 재현할 수 있다. 새로고침하면 계정과 세션이 초기화된다. 비밀번호는 브라우저 저장소에 기록하지 않는다.

Mock 계정은 실제 서버 세션을 만들지 않으므로 접수·사진 API 권한을 제공하지 않는다. 접수 및 사진 통합 검증은 Mock 설정을 제거하고 실제 서버 계정으로 진행해야 한다. 운영 빌드에 Mock 설정을 넣지 않는다.

## 검증

- 전체 프론트 테스트 및 프로덕션 빌드 실행.
- 회원 입력 조건, 요청 payload, 이름 공통 상태 반영, 현재 비밀번호 오류 시 로그인 유지, 성공 시 재인증 전환을 테스트한다.
- 사진 형식·크기·개수, 드롭, 업로드 실패, 완료 화면의 업로드, 재진입·StrictMode 중복 방지, 조회·삭제를 테스트한다.
- 기존 자동 접수·추가 답변·수동 접수 테스트를 유지한다.

## 통합 검증 잔여 항목

- 실제 회원 API와 쿠키·CSRF·다른 세션 무효화 확인.
- 실제 서버에서 자동 접수·추가 답변 후 접수·수동 접수의 사진 저장 및 조회·삭제 확인.
- PC·모바일 브라우저 시각 검수와 `/signup`, `/profile` 직접 접속·새로고침 확인.
- 확정된 신규 부서 유형 코드 수신 후 연결 확인. 부서 매칭·AI 판단·배포 설정은 변경하지 않았다.

## 2026-10-30 코드 대조 점검

현재 작업 트리의 구현을 피드백과 대조했다. 아래 완료 표시는 코드 확인 기준이며 실행·실서버 검증 완료를 뜻하지 않는다. 최초 점검 이후 아래 누락 사항을 수정했고, 완료 여부를 갱신했다.

- [x] 회원 API 6개 경로와 요청 본문 연결, 기존 api/post/patch 및 쿠키·CSRF 처리 유지 (`api.ts`, `account.tsx`, `App.tsx`).

- [x] 로그인 회원가입 버튼, 상단 회원정보 링크, `/signup`·`/profile` 경로, 로그인·세션 검사 유지.

### 누락 사항 수정 및 검증 결과

- [x] **완료 화면 이탈 시 사진 자동 업로드 누락 수정.** AutoUploadPhotos의 업로드 시작을 화면 cleanup과 분리했다. 최초 목록 조회 중 상세로 이동해도 업로드가 계속되며, 세션 변경 시에는 시작하지 않는다. 기존 attempted/busy/uncertain 중복 방지와 실패 후 자동 재전송 금지는 유지한다.
- [x] **학생 상세 내부 코드 정리.** 분류는 사용자용 이름으로 표시하며, 미정의 코드는 '기타 문의·불편'으로 표시한다. 학생 타임라인은 접수·상태·배정·이관 안내 이벤트만 표시하고 내부 유사도 검토·사건 연결 이벤트는 숨긴다. 관리자 상세의 기존 이벤트 표시는 유지한다.
- [x] **학생 오류 화면의 개발 정보 정리.** 기본 ErrorBox에서 오류 code와 영문 필드 키를 숨기고 오류 설명·필드 메시지를 유지한다. showDetails 옵션으로 명시적으로 상세 정보를 표시할 수 있다. 회원 입력칸 아래 fieldErrors 처리는 유지한다.
- [x] **오류 분기의 뒤로가기 명칭 수정.** 상세 조회 실패 시에도 학생은 '접수내역으로'를 표시한다.
- [x] **신규 유형 대응.** 수동 접수의 기본 유형 목록에 서버 report-types의 category/subcategory 쌍을 중복 없이 합친다. 새 유형은 서버 workName을 사용하고, 학생 목록·상세에서 알 수 없는 내부 코드는 노출하지 않는다. 확정된 코드의 실제 응답 확인은 통합 검증 때 필요하다.
- [x] **Mock 입력 검증 보완.** 회원가입·이름·비밀번호 변경 요청의 입력 조건과 fieldErrors를 검증하고, 이름만 trim한다. 학생 권한 고정, 중복 아이디, 현재 비밀번호 불일치 시 세션 유지, 성공 후 세션 만료 및 공백 포함 비밀번호 재로그인을 테스트했다. Mock은 실제 쿠키·CSRF를 만들지 않으므로 실제 403 동작은 서버 통합 검증 범위다.
- [x] **테스트·타입 검사·빌드.** 설치된 Node 런타임을 찾아 실행했다. 전체 프론트 테스트 10개 파일·97개 테스트 통과, TypeScript 검사 통과, Vite 프로덕션 빌드 통과. 최초 점검 시 npm 명령을 찾지 못했던 문제와 구분한다.
- [x] **추가 회귀 검증.** 완료 화면의 최초 조회 중 이탈 후 정상 업로드, 세션 정리 후 업로드 중단, 학생 내부 코드 숨김, 오류 분기 명칭, 신규 서버 유형 선택, 회원 Mock 계약 테스트를 추가했다. 기존 접수·사진 실패·중복 방지·조회·삭제 테스트도 통과했다.
