# 프런트엔드 구현·검증 기록

최종 확인: 2026-10-11 14:16 KST. 이 문서는 React 프런트엔드의 실행 결과이며, 실제 AI 공급자·MySQL 연결·브라우저 전체 E2E를 대신하는 증거가 아니다.

## 실행한 검증

작업 위치: `frontend/`

- `npm.cmd run build`: PASS. TypeScript 검사와 Vite 프로덕션 빌드 성공. 1,689개 모듈, JS 315.44 kB / gzip 99.59 kB.
- `npm.cmd test`: PASS. Vitest 테스트 파일 3개, 테스트 12개 성공.
- 실제 설치 버전: Node 24.20.0, npm 11.19.0, React 19.3.0, React Router 7.18.4, TypeScript 5.9.3, Vite 7.3.7, Vitest 3.2.7. 재현 버전은 `package-lock.json`에 기록되어 있다.

테스트 범위:

1. 변경 요청의 세션 쿠키 및 CSRF 헤더 전송, 로그인 후 토큰 갱신.
2. 서버 오류 코드 및 필드 검증 오류 보존.
3. 인증 요청의 401 발생 시 세션 만료 알림.
4. 네트워크 실패를 성공 응답으로 처리하지 않음.
5. 만료된 세션의 CSRF 토큰을 버리고 다음 로그인 전에 새 토큰 조회.
6. 근거 없는 질문은 답변 불가·미검증 표기를 보이고 신고를 저장하지 않음.
7. 추가 질문 재분석 시 스키마에 없는 `occurredOn`은 AI 입력에서 제외하고 사용자가 확인한 날짜는 화면에 보존.
8. AI 응답 없이 수동 신고 접수. 클라이언트는 부서 ID와 학생 ID를 지정하지 않음.
9. 관리자 완료 처리 시 공백 또는 빈 처리 결과 제출 차단.
10. 검증된 누수 라우팅 규칙이 없어도 수동 `FACILITY/LEAK` 신고를 선택할 수 있고, 관리자 확인 대상으로 안내.

11. 초기 인증 확인이 401이면 이전 사용자 초안·마지막 접수 ID를 제거한다.
12. 실행 중 세션 만료와 다음 로그인에서 이전 초안을 제거하며 앱과 무관한 저장 키는 유지한다.

이번 보안 검토에서 세션 만료 후 브라우저 초안이 남는 문제를 수정했다. API 응답을 Mock한 컴포넌트 테스트이므로 12개 성공을 실제 모델 정확도 또는 DB 통합 성공으로 해석하면 안 된다. 브라우저·백엔드 전체 통합 검증은 별도 실행 결과를 따른다.

## 구현된 화면

- 학생: 자연어 입력, 신고/질문 목적 선택, 추가 질문·재분석, 일반 질문 답변과 출처, 분석 실패 후 수동 신고, 최종 유형·위치·증상·발생일 수정, 접수번호, 내 신고 목록·상세·결과.
- 관리자: 상태별 신고 목록, 상세·이력, 검증된 활성 규칙 재배정, 처리 시작·완료, 유사 신고 후보와 점수/규칙 구분, 동일 사건/별도 사건/반려, 수동 사건 연결, 사건 상세·이력, 반복·재발 후보와 시간 불확실성, 재발 확인/반려.
- 공통: 로그인·로그아웃·세션 만료, 로딩·빈 목록·오류, 긴급 안내, DEMO/LIVE/RULE_ONLY 표기, 공식 출처 확인 여부, 학교 공식 접수가 아니라는 안내, 반응형 배치.

라우팅 유형 선택과 담당 부서 배정은 분리된다. 수동 선택 가능한 허용 유형도 검증된 규칙이 없으면 자동 부서 배정을 표시하지 않는다. 실제 배정은 서버가 다시 검증한다. 반복 후보 화면은 응답의 `aiMode`를 사용하며 전역 Embedding 설정만으로 LIVE라고 표시하지 않는다.

## 환경 관련 기록

최초 제한된 네트워크 설치는 DNS 오류로, 시스템 인증서를 사용하지 않은 재시도는 TLS 인증서 검증 오류로 실패했다. Windows 시스템 CA를 사용하는 다음 명령으로 인증서 검증을 유지한 채 설치에 성공했다.

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm.cmd install --cache .npm-cache --no-audit --no-fund --fetch-retries=0
```

Codex Windows 샌드박스에서 Vite/Vitest의 `realpath` 호출이 EPERM으로 거절되어 동일 명령을 승인된 일반 실행으로 재검증했다. 애플리케이션 오류나 테스트 실패를 우회한 것은 아니다. 초기 UI 수정 중 JSX 문법 오류를 수정한 뒤 위 최종 빌드·10개 테스트를 다시 통과했다.

로컬 개발 실행:

```powershell
cd frontend
npm.cmd run dev -- --host 127.0.0.1
```

개발 서버는 `127.0.0.1:5173`에서 실행하며 `/api`를 `127.0.0.1:8080`으로 프록시한다. 비밀번호는 프런트엔드에 저장하거나 하드코딩하지 않는다.
