# 유사 신고·사건·재발 검증 기록

## 구현 범위

`SimilarityService`는 신고 저장 트랜잭션이 커밋된 뒤 호출된다. Embedding 공급자 오류는 이미 저장된 신고를 취소하지 않는다. 벡터가 있으면 실제 응답 모델명과 JSON 벡터를 저장하고, 모델·차원·유한성·비영벡터 조건을 확인한 뒤 코사인을 계산한다. Embedding을 사용할 수 없거나 비교 모델·차원이 맞지 않으면 규칙 후보이며 점수는 `null`, 후보의 `aiMode`는 `RULE_ONLY`다.

후보 검색은 유형, 건물, 알려진 층·호실, 접수 시각 창을 적용한다. 알려진 건물·층·호실의 충돌은 제외한다. 호실이나 층이 일부 없으면 확정 사실을 만들지 않고 불확실성을 표시한다. 후보 쌍은 작은 신고 ID를 왼쪽에 두고 유일 제약으로 중복 저장을 막는다. 재계산이 관리자의 검토 결정을 덮어쓰지 않는다.

기본 임계값 `0.82`와 접수 시간 창 `30일`은 명세의 실험 예시를 사용했다. **실제 모델 또는 현장 데이터로 최적화·검증한 값이 아니다.** `skope.similarity.threshold`와 `skope.similarity.window-days`로 조정할 수 있다. 별도 벡터 DB, RAG, 자동 사건 병합은 사용하지 않는다.

`IncidentService`는 관리자 처리 시작 시 단독 사건을 만들거나 관리자 `SAME_INCIDENT` 판단으로 신고를 연결한다. 서로 다른 사건 또는 이미 종료된 사건은 자동 병합하지 않는다. 기존 `RELATED_DISTINCT`/`REJECTED` 결정은 수동 연결이나 제3의 신고를 이용한 연결로도 우회할 수 없다. 신고 수와 사건 수는 분리되며, 소속 신고 모두가 처리 결과를 갖고 완료되었을 때만 사건이 종료된다.

재발은 같은 유형·장소의 **종료된** 과거 사건과 비교한다. 발생일이 있으면 종료 날짜보다 뒤인 날짜를 요구한다. 같은 날은 `DATE` 정밀도로 선후를 알 수 없어 보수적으로 제외한다. 발생일이 없으면 접수 시각을 비교하되 `REPORTED_AT_ONLY`와 불확실성 설명을 유지한다. 관리자가 확인해도 누락된 발생일을 만들어 넣지 않는다. 미래 고장 확률을 예측하는 기능이 아니다.

## 트랜잭션 및 동시성

- 신고 행을 ID 오름차순으로 잠근 뒤 사건 행을 ID 오름차순으로 잠근다. 핵심 변경은 `READ_COMMITTED`에서 수행한다.
- 상태 변경자가 사건 잠금을 얻은 뒤 최신 완료 건수를 읽어 마지막 완료를 놓치지 않게 한다. 집계 시 다른 신고 행을 추가로 잠그지 않아 반대 순서 잠금을 피한다.
- 재발 검토는 현재 소속 신고를 먼저 잠근 뒤 사건을 잠근다. 그 사이 멤버십이 바뀌면 409로 재검토를 요구한다.
- 사건 연결·유사 검토·재발 검토 이력은 변경과 같은 트랜잭션에 저장한다. 실패한 이력 저장은 사건 생성·연결도 롤백한다.
- 대규모 운영 부하·분산 환경·복잡한 수동 사건 재편집은 검증 범위 밖이다.

### 사건 시나리오

1. 신고 3건을 관리자 검토 후 사건 1건으로 연결하고 모두 완료됐을 때만 종료.
2. 서로 다른 열린 사건 및 종료된 사건 병합 거절.
3. 일부 신고가 완료됐어도 열린 사건에는 같은 장소의 신규 중복 신고 연결 가능; 다른 호실 거절.
4. 확인된 이후 발생일로 별도 재발 사건 생성·확인/반려·검토자/시각/이력 저장.
5. 발생일 없는 임시 후보와 관리자 확인 후에도 접수 시각의 불확실성 유지.
6. 미종료 과거 사건, 같은 날·미래 발생일, 다른 유형·장소, 자기 참조 거절.
7. 별도 사건·후보 반려 결정은 사건을 생성하지 않으며 이력 저장.
8. 이력 저장 오류 시 사건 생성·연결·판정 모두 롤백.
9. 두 관리자의 동시 마지막 신고 완료에서도 사건 종료를 누락하지 않음.
10. **후속 추가 회귀:** 기존 별도 사건 결정을 수동 또는 제3 신고 연결로 우회하지 못함.

실제 신고의 동일 사건/재발 판정 품질, 실제 모델의 오탐·누락, 임계값 튜닝은 남은 검증 작업이다.
