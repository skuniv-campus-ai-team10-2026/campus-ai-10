# 표현 변형 오류 수정 및 검증

> 과거 합성 장소를 포함한 실행 기록입니다. 원본 입력·응답은 보존했습니다. 현재 시연 장소와 향후 평가 기본값은 [실제 장소 예시 정정 기록](campus-locations-review.md)에 따릅니다. 이 문서의 LIVE 성적은 새 장소의 검증 결과가 아닙니다.

수정·로컬/LIVE 실행: 2026-10-19 KST. 결과 검토·최종 HTTP 확인: 2026-10-20 KST.

## 변경 범위

제품 파일은 두 개다. API 요청·응답 계약, DB 스키마, 모델, 프런트엔드는 변경하지 않았다.

- `backend/src/main/java/edu/skope/ai/AiService.java`: 사투리·오타·축약·감정 표현에서도 실제 증상을 보존하고, 원문 근거는 그대로 인용하도록 프롬프트 보완. `개더움`처럼 증상이 명확한 표현과 단순 불편 호소를 구분하며 설비 고장·원인을 만들지 않도록 했다. 프롬프트 버전 `hybrid-intake-v2`.
- `backend/src/main/java/edu/skope/ai/ClarificationPolicy.java`: 원문에 연결 성공과 인터넷 사용 불가가 함께 명시된 한국어/영어 혼합 표현을 인정. `먹통`만 있거나 연결 상태가 불확실한 경우는 추가 질문 유지. 모델이 부정·불확실 문구를 잘라 근거로 제시해도 인정하지 않도록 해당 경로의 문맥 검증 추가. 정책 버전 `hybrid-check-v3`.

등록된 표현만 지원하는 결정적 정책의 한계가 사라진 것은 아니다. 새로운 언어 표현 전체의 이해를 보장하지 않는다.

### 수정 전후 비교 및 새로운 문장

| ID | 문장 요약 | 수정 전/기대 | 수정 후 실제 |
|---|---|---|---|
| D1 | 와파 connected는 됨 근데 인터넷 먹통임 | 기존: AI 이해 성공, 서버 재질문 | 연결 성공·인터넷 불가 보존, 질문 없이 접수 |

| H1 | 솔빛관608호 개추움ㅠ 손 시림 | 새 평가: 추위를 보존, 난방 고장 추정 금지 | 추위·시린 손 보존, 질문 없이 접수 |

| H3 | 엄청 더운 건 아니고 그냥 불편 | 새 평가: 더위로 확정 금지, 실제 증상 질문 | 증상 null, ISSUE_UNCLEAR / NEEDS_INPUT |
| H4 | 와파 먹통임. connected인지는 모르겠음 | 새 평가: 연결 상태 확정 금지, 장애 방식 질문 | 일반적인 Wi-Fi 문제로 보존, SYMPTOM_DETAIL / NEEDS_INPUT |

H3는 기존 병합 정책이 초기 null 증상을 `reviewFields: SYMPTOM`, `CONFLICT`로도 표시한다. 실제 표시될 다음 질문은 올바른 ISSUE_UNCLEAR다. 이후 추가 답변에서 검토 표식이 해소되는지는 이번 평가 범위 밖이다. 더위·추위는 기존 분류 체계상 OTHER/UNKNOWN 및 총괄 검토로 접수되며, 냉난방 담당 부서를 새로 자동 배정하도록 확대하지 않았다.

## 비용 및 증거

- 실제 새 OpenAI 호출 **6회**, Embedding **0회**, 유료 재시도 **0회**. 기존 12응답 재생 및 HTTP 6건은 외부 API 0회.
- 모델 `gpt-6-luna`, Standard/default, reasoning none, 출력 상한 2,048토큰.
- 입력 **10,148**, 출력 **974**, 총 **11,122토큰**.
- 입력 전체를 캐시 쓰기 단가로 계산하고 캐시 할인을 무시한 보수적 추정 **$0.0017555**. 사전 상한 **$0.05**, 보수적 최대 예약 **$0.049788** 이내. 청구 확정액은 아니다. [공식 모델 요금](https://developers.openai.com/api/docs/models/gpt-6-luna), 2026-10-19 확인.
- 기대 결과는 `language-variation-v2.json`에서 출력 전 고정. SHA256 `757d37542162f7302898b100132ff7efe1a1cbd9ea3b7a248e21dbd6828180e0`; 실행 및 검토 후 동일 해시 확인.
- 원본·후처리·토큰·판정: `language-variation-v2-results.json`. 최종 소스 해시가 LIVE 당시와 동일함을 재확인.
- 기존 응답 재생: `language-variation-v2-replay.json`. HTTP 저장·학생 조회: `language-variation-v2-http.json`.
- `scripts/Test-LanguageVariation.ps1 -Mode PREPARE`는 외부 호출 없이 요청 크기와 상한 확인. `-Mode LIVE`는 기존 영속 캐시를 재사용하며 실패 시 재시도하지 않는다. 6회 누적 한도는 소진했다.

## 테스트 파일과 현재 실행 환경

- 수정: `backend/src/test/java/edu/skope/ai/ClarificationPolicyTest.java` — 혼합 표현, 부정·불확실 근거, 잘못 잘라낸 인용, 장소 답변 이후 근거 유지, 증상 정정 후 폐기.
- 추가: `LanguageVariationReplayTest.java` — 저장된 12개 실제 응답 재생.
- 추가: `LanguageVariationVerificationTest.java`, `scripts/Test-LanguageVariation.ps1` — 고정 6건, 비용·횟수 제한, 실패 후 유료 재호출 방지, 원본/최종 출력 저장.
- 현재 로컬 서버는 **수정된 빌드 + 임시 H2 + 정확히 일치하는 저장 LIVE 응답 재생**이다. 모델 응답을 수작업으로 만든 DEMO는 아니지만, 새 실시간 추론도 아니다. 임의 입력·추가 답변에는 캐시가 없으므로 정상적인 일반 LIVE 실험 환경으로 사용하면 안 된다.
- 브라우저 열기 요청은 앱에 전달했으나 표시 완료를 시각적으로 확인하지는 못했다. 격리 H2 테스트 계정으로 로그인 후 `내 신고`에서 D1/D2를 포함한 저장된 4건을 볼 수 있다. 기존 MySQL 계정·데이터와는 별개다.

이번 수정의 두 대상 오류는 저장 응답 정책 회귀와 새 LIVE 추론으로 각각 해소를 확인했다. 새 문장 4건을 포함해 문장당 1회 측정한 결과이므로 표현 전반의 정확도나 반복 안정성이 보장된다는 의미는 아니다. 추가 유료 호출은 종료했다.
