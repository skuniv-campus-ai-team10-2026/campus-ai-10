평가 기간: 2026-10-18~19 KST. 제품 코드는 수정하지 않았다. 첫 표준어 입력은 18일, 나머지는 19일에 실행했다.

## 결과

## 확인한 오류와 수정 권고

### P2: 서버 정책의 표현 인식 한계

입력: `다온관 410호 와파 connected는 됨 근데 인터넷 먹통임.`

원본 AI는 `REPORT / IT / WIFI`, 증상 `와이파이는 연결되지만 인터넷이 되지 않음`, `missingFields: []`, `reason: NONE`을 반환했다. 원문 근거도 `connected는 됨 근데 인터넷 먹통임`으로 제공했다. 그러나 화면은 “와이파이 연결 자체가 안 되나요, 연결 후 인터넷이 안 되나요?”라고 재질문했다.

`ClarificationPolicy.java`의 55행은 원문 근거가 `wifiDetail`을 통과해야 상세 증상이 충분하다고 인정한다. 96행의 한국어 표현 정규식은 이 혼합 표현을 인식하지 않는다. 모델의 해석이 맞아도 서버가 과도하게 제한하는 사례다.

최소 개선 방향: 원문 근거 검증을 유지하면서, 연결 상태와 인터넷 사용 상태의 의미를 검증 가능한 형태로 반영하도록 정책을 보완한다. 모델 요약을 무조건 신뢰하거나 모든 재질문 조건을 해제하는 방식은 피해야 한다. 저장된 응답으로 결정적 정책 회귀 검증을 먼저 하고, 새로운 표현은 별도 평가로 확인한다.

### P4: LLM의 축약 표현 이해 실패

입력: `아 진짜 해든관502호 개더움;;`

원본 AI는 장소·층은 추출했지만 `intent: UNKNOWN`, `symptom: null`, `missingFields: [SYMPTOM]`, `reason: ISSUE_UNCLEAR`를 반환했다. 실제로는 더위가 명시돼 있으나 “어떤 문제가 있나요?”라고 판단했다. 서버도 증상 누락 판단에 따라 일반적인 추가 질문을 표시했다.

최소 개선 방향: 기존 프롬프트에서 감정 표현과 실제 증상을 분리하고 축약·비속어 안의 증상을 보존하도록 지침을 보완한다. 특정 단어 하나를 추가해 통과시킨 결과를 일반 정확도 개선으로 보고하지 말고, 보지 않은 축약 표현으로 재평가한다. 제품 변경 및 수정 후 검증은 아직 하지 않았다.

두 오류 모두 잘못된 자동 접수나 데이터 파괴보다는 불필요한 재질문 문제다. 다만 자유로운 자연어를 이해하고 질문 부담을 줄인다는 핵심 시연 목표와 관련되므로 제출 전에 보완할 가치가 높다.

## 실제 연동 범위와 사용량

- 실제 OpenAI `gpt-6-luna`, `service_tier: default`: 12회 요청, 12회 응답 성공, 유료 재시도 0회.
- 입력 18,729토큰, 출력 1,982토큰, 합계 20,711토큰.
- 입력 캐시 할인을 적용하지 않은 추정 비용: **$0.0028639**. 입력 $0.10/백만, 출력 $0.50/백만 기준(2026-10-18 확인한 [모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)); 청구 확정액은 아니다.
- 사전 상한 12회 / $0.10. 호출별 보수적 예약액을 적용한 최대 예약 $0.084576 이내에서 실행했다.
- Embedding 0회, RULE_ONLY. DB는 격리된 메모리 H2이며 기존 MySQL을 사용하지 않았다. 학교로 전송하지 않았다.
- 실제 React → Spring Boot → OpenAI → H2 접수 → 학생 상세 화면을 확인했다. MySQL, 관리자 처리, 유사도, 후속 답변 병합은 이번 추가 검사 범위가 아니다.
- 현재 브라우저는 마지막 모호한 표현의 추가 질문 화면에 열려 있다. 평가용 중계는 고정 12문장만 허용하며, 동일 요청은 저장된 응답을 재사용한다. 임의의 새 입력·추가 답변을 시험하는 일반 LIVE 환경은 아니다.
