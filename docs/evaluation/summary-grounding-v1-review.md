## 결론

## 원인과 수정 판단

### 기존 요약 오류 2건: LLM 분석 + 서버 검증 공백

LLM이 일반적인 “안 됨”을 구체적인 “연결 안 됨”으로 바꿉니다. 서버는 원문 근거가 부족하면 후속 질문을 유지하지만, 이미 만들어진 symptom의 단정적인 표현은 그대로 둡니다. 질문 판단 성공과 보고서 내용 정확성은 별개라는 점이 확인됐습니다.

최소 개선 후보는 원문에 없는 세부 장애 양상을 추가하지 않는 프롬프트 조건, 그리고 증상 상세 정보가 미확정인 상태와 보고서 요약 사이의 일관성 검사입니다. 단순히 모든 구체적인 증상을 삭제하면 G02·G08처럼 사용자가 명확히 말한 사실도 잃으므로 피해야 합니다. 수정 후에는 기존 실패 사례와 이번 정상 대조 사례를 함께 회귀 검증해야 합니다.

### G07: 요약 밖에서 발견한 후속 질문 문제

AI는 “강의실이 너무 더워요”를 symptom으로 추출하면서도 intent UNKNOWN, missingFields SYMPTOM, assessment ISSUE_UNCLEAR를 반환했습니다. rationale은 “더운 상태만으로는 구체적인 설비 고장인지 확인이 필요”입니다. 최종 서버 질문은 “어떤 점이 불편한가요? 냉난방, 책상·의자, 소음처럼 실제 문제를 알려주세요.”가 됐습니다.

원인이 확인되지 않은 것과 관찰된 불편이 없는 것을 혼동한 결과입니다. 에어컨 가동 여부를 더 물을 필요가 있는지는 별도 정책 판단이지만, 이미 알려준 불편 자체를 처음부터 다시 묻는 방식은 개선 대상입니다. 이 항목은 실행 후 발견한 부가 관찰이며, 고정한 요약 점수나 정답을 바꾸지 않았습니다.

G12의 장학금 문의는 QUESTION으로 인식했지만 category OTHER / UNKNOWN입니다. 부서 배정상 적절한지는 별도 검토 대상으로 남기며 이번 요약 검증에서 분류 오류라고 확정하거나 수정하지 않았습니다.
