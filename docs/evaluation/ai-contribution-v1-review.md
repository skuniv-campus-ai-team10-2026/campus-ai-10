# AI와 서버 규칙의 기여도 비교 — 2026-10-18

결론: 현재 AI는 단순 장식이 아닙니다. 기존 DEMO의 키워드 추출을 실제 AI 응답으로 대체하면 의미 해석과 불필요한 질문이 개선됩니다. 동시에 AI 출력만으로는 이전 정보 보존·질문 종료·충돌 판단이 불안정하므로 서버 정책도 필요합니다. 이번 결과는 학습 모델 전환의 필요성이나 성공 확률을 입증하지 않습니다.

## 실행 범위와 비교 기준

- 기존 `hybrid-v1`, `hybrid-stress-v1`의 실행 전 고정 정답과 저장된 실제 LIVE 응답을 재사용했습니다. 정답은 수정하지 않았습니다.
- 49개 예정 단계 중 46개 응답 재생: 최초 입력 37건, 추가 답변 9건. 원본 LIVE 응답이 없는 S26-2, S26-3, S28-2는 미검증입니다.
- 규칙 방식: 기존 DEMO 키워드 추출 + 현재 서버 병합·질문 정책. 최적으로 개발한 모든 규칙 기반 시스템을 대표하지 않습니다.
- AI 원출력: 저장된 API 응답의 JSON. `assessment.reason != NONE`을 질문 제안으로 측정했습니다. AI는 원래 최종 접수 결정자가 아니라 분석·질문 제안 역할로 프롬프트되어 있으므로 독립 완성 서비스와의 비교가 아닙니다.
- 현재 결합 방식: 동일한 저장 응답을 현재 `AiService`로 재생했습니다. 네트워크 호출 함수는 저장 응답만 반환하도록 테스트에서 대체했습니다. DEMO 결과를 LIVE 결과로 부르지 않습니다.
- 최초 입력을 주 비교 대상으로 삼았습니다. 추가 답변은 양쪽에 당시 저장된 동일한 이전 상태를 제공한 통제 비교이며, 각각의 방식으로 처음부터 대화를 진행한 결과가 아닙니다. 규칙 방식의 후속 입력에도 기존 AI 분석 정보가 포함됩니다.
- 질문 여부는 정답 상태가 CONTINUE/COMPLETE인 경우만 비교했습니다. MANUAL_REVIEW 1건은 AI 원출력에 대응 상태가 없어 질문 지표에서 제외했습니다.
- 추출 정보는 기존 정답에 명시된 intent/report 필드만 채점했습니다. 정답이 없는 모든 필드의 품질까지 검사한 정확도가 아닙니다.

## 측정 결과

### 최초 입력 37건: 추가 질문 필요 여부

정답상 질문 필요 14건, 질문 불필요 23건입니다. Precision은 질문한 경우 중 실제로 필요한 비율, Recall은 필요한 질문을 놓치지 않은 비율입니다.

| 방식 | 필요한 질문 탐지 | 불필요한 질문 | 필요한 질문 누락 | Precision | Recall | 질문 여부 일치 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 규칙 방식 | 13 | 8 | 1 | 61.9% | 92.9% | 28/37 |
| AI 원출력의 질문 제안 | 13 | 0 | 1 | 100% | 92.9% | 36/37 |
| 현재 AI + 서버 정책 | 14 | 0 | 0 | 100% | 100% | 37/37 |

최초 입력의 명시적 필드 조건 20개는 규칙 16/20, AI 원출력 20/20, 결합 방식 20/20입니다. 상태·질문 이유·명시 필드 조건을 모두 만족한 최초 입력은 규칙 26/37, 결합 방식 37/37입니다. AI 원출력에는 서버 상태가 없으므로 같은 전체 통과율을 부여하지 않았습니다.

### 추가 답변 9건: 동일한 기존 맥락 제공

| 방식 | 질문 지표 TP/FP/TN/FN (8건) | Precision / Recall | 명시 필드 조건 통과 (14개) | 전체 고정 조건 통과 (9건) |
|---|---|---|---|---|
| 기존 규칙 방식 | 3 / 0 / 5 / 0 | 100% / 100% | 11/14 | 8/9 |
| AI 원출력 | 2 / 2 / 3 / 1 | 50% / 66.7% | 12/14 | 해당 없음 |
| 현재 결합 방식 | 3 / 0 / 5 / 0 | 100% / 100% | 14/14 | 9/9 |

전체 46단계의 기존 고정 조건은 규칙 34/46, 결합 방식 46/46입니다. **이 수치는 전체 내용이 정확하다는 뜻이 아닙니다.** 아래 사후 내용 검토에서 채점 조건 밖의 문제를 발견했습니다.

## AI가 실제로 도움이 된 사례

| 사례 | 규칙 방식 | AI와 현재 결합 방식 |
|---|---|---|

| S17-1: “천장에 물방울이 맺혀 바닥으로 계속 떨어집니다” | 누수 유형을 놓치고 추가 질문 | LEAK로 해석 |

## 서버 정책이 필요한 사례

- **S28-1:** “다솜관 전체에서 와이파이가 안 돼요”에 AI는 질문 없음(NONE)을 제안했습니다. 서버는 실제 장애 양상이 부족하므로 증상 질문을 유지했습니다.
- **S25-3:** 이미 늘봄관 316호가 확인된 후 인터넷 페이지가 열리지 않는다고 답하자, AI의 제안 보고서에서 층이 사라지고 장소 질문이 다시 나왔습니다. LOCATION 업데이트는 KEEP이었으므로 서버가 기존 장소를 보존하고 질문을 종료했습니다. AI의 KEEP 선택 자체는 맞았고, 제안 보고서와 질문은 기존 맥락과 불일치했습니다.
- **S29-2:** “3층 403호”를 AI가 3층으로 확정하고 질문 없음으로 제안했습니다. 서버는 현재 프로젝트의 호실·층 일관성 정책에 따라 충돌로 처리했습니다. 이 정책이 모든 실제 건물의 호실 체계에서 옳다는 뜻은 아닙니다.
- **S29-3:** 층만 정정했는데 AI가 이미 확인된 Wi-Fi 증상을 다시 질문했습니다. 서버가 보존된 증상 정보를 사용해 종료했습니다.

현재 결합 방식이 고정 채점 조건에서 AI보다 나빠진 사례는 발견되지 않았습니다. 그러나 같은 사례로 정책을 개선해 온 개발 데이터이므로 새 문장에서도 항상 그렇다고 해석할 수 없습니다.

## 기존 채점 밖에서 확인한 문제 — 점수와 분리

### 1. 질문 판단이 맞아도 요약은 과하게 확정될 수 있음

S04-1은 “와이파이가 안 돼요. 비밀번호 문제인지는 모르겠어요”인데 최종 분석의 symptom이 “와이파이가 연결되지 않음”입니다. S28-1도 “안 돼요”를 “연결되지 않음”으로 요약합니다. 서버는 둘 다 증상 질문을 유지하지만 이 단정적인 요약까지 고치지는 않습니다. S25-1, S26-1, S30-1에서도 유사한 표현이 관찰됩니다.

- 원인: LLM이 모호한 장애 표현을 구체적인 연결 장애로 바꾸고, 현재 서버 정책은 질문 여부를 제어하지만 요약의 근거 충실성 전체를 검증하지 않습니다.
- 영향: 추가 답변 전 화면 또는 미완성 상태의 관리자 검토 경로에서 근거 없는 세부 증상을 사실처럼 받아들일 가능성이 있습니다. 이번에는 DB 저장·브라우저 노출 경로까지 추가 검증하지 않았습니다.
- 권장 최소 개선: 원문에 없는 구체적 장애 양상을 요약에 추가하지 않도록 프롬프트/출력 정책을 보완하고, 증상 미확정 상태와 요약 표현을 일치시키는 검증을 추가합니다. 사례별 키워드 규칙만 계속 추가하는 방식은 권하지 않습니다.
- 이번에는 제품 코드를 수정하지 않았습니다. 위 관찰은 실행 후 내용 검토이며 기존 고정 점수를 소급 변경하지 않았습니다.

### 2. DEMO 통과가 내용 정확도를 보장하지 않음

S25-3의 규칙 결과는 기존 고정 조건을 통과하지만, “연결은 되는데 인터넷 페이지가 열리지 않아요”라는 답변을 증상에 반영하지 못하고 기존 “연결이 되지 않음”을 유지했습니다. 해당 단계의 기존 정답에는 최종 증상 조건이 없었습니다. S19-1에서는 지시문 속 999호를 층 9로 해석하기도 했습니다. LIVE 결합 결과에서는 이 두 문제가 관찰되지 않았습니다.

## 학습 모델 전환 판단

이번 결과만으로 바로 전환할 이유는 부족합니다. AI가 의미 해석을 담당하고, 서버가 정보 보존과 접수 정책을 담당하는 현재 역할 분담의 효과가 확인됐습니다. 반면 LLM의 맥락 유지·모호한 표현의 과도한 구체화에는 개선 여지가 있습니다.

우선순위는 (1) 위 요약 충실성 문제를 개선 대상으로 확정, (2) 팀원이 독립 작성·검수한 새 문장을 별도 평가셋으로 고정, (3) 현재 프롬프트와 개선 프롬프트를 같은 조건에서 비교하는 것입니다. 예를 들어 팀원 3~5명이 총 30~50개의 최초 입력·정정 답변을 작성하고 다른 사람이 정답을 검수할 수 있습니다. 이 수량은 시작 규모 제안이며 통계적 충분성을 보장하지 않습니다.

그 과정에서도 같은 의미 해석 오류가 반복되고 충분한 양질의 학습·검증 데이터가 확보될 때 추가 학습을 비교 후보로 검토합니다. 학습 모델을 실제로 훈련·평가하지 않았으므로 개선 확률을 숫자로 제시할 근거는 없습니다. 이번에는 임베딩과 유사 신고 검색도 재평가하지 않았으며, 이 결과를 검색 성능 개선 근거로 사용하면 안 됩니다.
