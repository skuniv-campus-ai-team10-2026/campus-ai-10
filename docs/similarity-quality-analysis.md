# 유사 신고 누락 원인 분석

분석 대상은 변경하지 않은 `evaluation/holdout-v1.json`의 20쌍이며, 기존 실제 API 결과는 `evaluation/holdout-v1-live-results.json`이다. 정답 라벨을 본 뒤의 개선 평가이므로 독립된 holdout 성능이나 실제 학교 데이터의 정확도로 해석하지 않는다.

기존 평가기는 각 쌍을 격리된 H2 메모리 DB에 저장하고 Embedding 2개를 얻었지만, 후보로 남은 쌍의 점수만 결과 파일에 기록했다. 프로세스가 종료되어 제외된 쌍의 원래 벡터와 정확한 점수는 복원할 수 없다. 결과의 `score: null`은 Embedding 실패 또는 점수 0을 뜻하지 않는다.

기존 탐지 P07은 DB 반올림 점수 0.8576, P09는 0.8630이다. 기존 전체 결과는 TP 2 / FP 0 / TN 11 / FN 7, Precision 100% (2/2), Recall 22.2% (2/9)이다. 양성 후보 2개에서 얻은 Precision만으로 운영 품질을 보장할 수 없다.

## 진단 및 비용 재사용 변경

`SimilarityService.diagnose`는 실제 후보로 채택되지 않은 쌍에서도 원래 코사인 점수, 장소 정규화 결과, 유형·건물·층·호실·시간·임계값 조건을 각각 반환한다. 외부 API를 호출하지 않으며 서버 API에 학생 원문을 추가 공개하지 않는다.

현재 제출된 신고의 원문·분류·장소·증상은 생성 후 수정되지 않는다. 따라서 동일한 모델의 유효한 벡터가 DB에 있으면 재색인에서 그대로 재사용한다. 벡터가 없거나 잘못되었거나 설정 모델이 바뀌었을 때만 다시 생성한다. 앞으로 해당 입력을 수정하는 기능이 생기면 반드시 벡터 무효화 또는 입력 해시 검증을 함께 구현해야 한다.

모델 변경 후 새 Embedding 생성이 실패하면 이전 벡터는 DB에 보존하되 이번 비교에서는 사용하지 않는다. 아직 검토되지 않은 후보의 예전 점수는 `null`과 RULE_ONLY 사유로 갱신한다. 명시적인 RULE_ONLY 모드에서도 재색인 시 기존 LIVE 점수를 그대로 표시하지 않는다. 이미 검토한 관리자의 결정·근거는 보존한다. 조회만 하는 경우에는 마지막으로 저장된 검토 결과를 반환하므로, LIVE 표시가 현재 조회 시점의 새 API 호출을 뜻하지는 않는다.

원래 평가의 40개 입력은 왼쪽 문장이 모든 쌍에서 중복되어 고유 입력 21개로 줄어든다. 2026-10-12 실제 Embedding 요청 21회로 벡터를 다시 측정했고, 나머지 19번의 동일 입력은 캐시를 재사용했다. 벡터·모델·입력 해시·응답 사용량은 `.runtime/ai-quality-cache/v2`에 보존했다. 아래 숫자는 이 새 실행의 실제 벡터에서 계산한 값이며, 원래 실행에서 미보존한 숫자를 복원했다고 주장하지 않는다. 같은 캐시로 수정 전후 정책 및 여러 임계값의 Precision·Recall을 계산할 때는 추가 API 호출이 필요 없다.

기본 임계값은 0.82로 유지했다. 추가 검토 후보는 **양쪽 모두 IT/WIFI, 기존 장소·시간 조건 통과, 양쪽 모두 명시적인 네트워크 연결 장애 표현, 실제 코사인 0.70 이상**인 경우로 한정했다. 연결 끊김·단절·반복 재연결·연결 불안정·무선망 꺼짐·접속 불가 표현을 사용한다. 안내 표지·스티커·계정 보안·비밀번호 등의 다른 문제, 정상 상태·문제 부정·연결을 끊는 방법 문의가 섞이면 이 보조 경로를 적용하지 않는다. 관리 화면의 후보 사유와 진단 결과에는 `CONNECTIVITY_SYMPTOM_SUPPORT`를 일반 임계값 통과 및 RULE_ONLY와 구분한다.

이는 현재 개발 평가셋에서 관찰한 오류를 고친 제한적인 보조 규칙이다. 새로운 기능 분류나 다른 신고 유형의 기준으로 확장하지 않았다. 별도 사람 라벨 평가셋에서의 일반화는 미검증이다. 한국어 부정·인용·복합 증상을 모두 이해하는 규칙이 아니며, 모호한 문장을 보조 경로에서 보수적으로 제외할 수 있다. 기본 0.82 경로에는 기존 기준이 그대로 적용되므로 높은 점수의 다른 의미 문제까지 완전히 해결했다고 주장하지 않는다.

## 같은 벡터로 확인한 최종 수정 전후 결과

2026-10-13 01:01 KST [오프라인 재생](evaluation/quality-v2-replay-results.json)은 저장된 실제 Embedding을 현재 `SimilarityService`의 H2 색인 경로에 넣었다. 쌍마다 진단 함수의 판단과 실제 DB 후보가 같은지도 검증했다. 고정 라벨·원래 LIVE 결과·새 LIVE 결과·캐시는 변경되지 않았으며, 이 재생에서 외부 호출은 **0회**였다. 벡터 조회 40건은 모두 캐시 재사용이다.

| 평가 | TP | FP | TN | FN | Precision | Recall | 상태 |
|---|---:|---:|---:|---:|---:|---:|---|
| 기존 0.82 기준, 동일 실제 벡터 | 2 | 0 | 11 | 7 | 100% | 22.2% | 누락 7쌍 |
| 수정한 조건부 보조 기준, 동일 실제 벡터 | 9 | 0 | 11 | 0 | 100% | 100% | 개발 평가 20쌍 통과 |

P01–P06·P08의 누락 7쌍이 보조 경로로 회복됐다. 원래 통과했던 P07·P09는 기본 0.82 기준에서 그대로 통과했다. 음성 11쌍도 계속 제외됐으며, P18·P19의 오탐은 추가되지 않았다. 해당 20쌍에서 미개선 항목은 없지만, 장소 정규화·유형·시간 조건은 원래도 적절하게 작동했으므로 이 영역의 개선 성과로 계산하지 않았다.

모델 벡터가 없는 DEMO/RULE_ONLY는 이 보조 경로의 점수 조건을 검증할 수 없다. 과거 DEMO의 TP 9 / FP 2 결과를 실제 AI 개선 결과와 합산하지 않는다. 위 성능은 새 외부 API 재호출이나 브라우저 검증 결과가 아니라 **저장된 LIVE 벡터를 재사용한 H2 서비스 평가**다.

## 검증 상태

- 원래 누락 7쌍의 필터 단계: 코드·고정 fixture·기존 LIVE 결과를 대조하여 확인.
- 원래 누락 7쌍의 정확한 코사인 숫자: 미보존으로 복원 불가.
- 새 실제 벡터로 기존 누락 7쌍과 전역 임계값의 오탐 증가 재현: 성공.
- 진단·벡터 재사용·모델 갱신 실패·부정 표현·점수 하한·유형·장소·시간 경계 회귀 테스트: SimilarityServiceTest **45개 성공**. [최종 통합 회귀](evaluation/quality-final-regression-summary.json) 93개 성공 중 포함되며, SimilarityService fixture는 H2이다.
- 개선 정책의 같은 벡터를 이용한 수정 전후 비교: **성공**, TP 2→9 / FP 0 유지. 추가 실제 API 호출 없음.
- 별도 현장/사람 검수 평가셋의 개선 효과: 미검증.

관리자가 동일 사건 여부를 확인하는 원칙과 30일 접수 시간창은 유지한다. 후보가 선택되어도 자동 사건 병합이나 발생일 확정으로 이어지지 않는다.
