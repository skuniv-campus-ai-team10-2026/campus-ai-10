# 업무 그룹(workGroup)으로 새 물건 접수하기

기준일: 2026-10-27. `feature/work-group-routing` `6647c27`을 검토하고 `fix/work-group-corrections`에서 보완했다. 기준 `main`은 `ac233a7`. 이번 개발용 LIVE 검증은 LLM 5회, Embedding 0회다.

## 1. 왜 필요한가

기존 유형(와이파이·누수·전기·냉난방·정수기·집기·학적)에 없는 물건이 들어오는 경우가 있다. 예를 들면 거울, 빌린 실습복, 두고 온 옷, 연필 같은 것이다.
지금까지는 이런 신고가 모두 "기타(OTHER/UNKNOWN)" 하나로 들어갔다. 그래서 관리자는 어느 분야 일인지 알 수 없었고, 유사 후보도 장소만 같으면 만들어졌다.
이번 변경은 유형 코드를 늘리지 않는다. 대신 **처리 분야(업무 그룹)**, **대상(자유 문자열)**, **학교 관련성** 세 값을 함께 저장한다.

## 2. 새 필드 (모두 선택 입력)

| 필드 | 값 | 설명 |
|---|---|---|
| `workGroup` | `IT_SUPPORT`, `ELECTRICAL_MAINTENANCE`, `FACILITY_MAINTENANCE`, `SHARED_EQUIPMENT`, `ACADEMIC_ADMIN`, `GENERAL_REVIEW` | 처리 분야. 고정 6개라 물건이 새로 나와도 늘지 않는다. 부서 이름이 아니다 |
| `targetText` | 자유 문자열, 최대 100자 (예: "거울") | 명시된 물건을 일반적인 한국어 명칭으로 정리한다. 학생의 원문·근거는 별도로 유지한다. 배정 코드와 연결하지 않는다 |
| `campusRelevance` | `CAMPUS_FACILITY`, `SCHOOL_SERVICE`, `PERSONAL_ON_CAMPUS`, `OUT_OF_SCOPE`, `UNCERTAIN` | 학교 시설 / 학교가 빌려주는 물건·서비스 / 개인 물건 / 학교가 처리하지 않는 요청 / 아직 모름 |

- DB에 칼럼 3개를 추가했다(`V10__work_group_target.sql`, 모두 NULL 허용). 예전 마이그레이션은 고치지 않았다.
- **기존 유형은 업무 그룹이 고정이다.** 아래 표가 항상 이긴다. AI나 화면이 다른 값을 보내도 서버가 표 값으로 바꾼다.

| 기존 유형 | 업무 그룹 |
|---|---|
| WIFI | IT_SUPPORT |
| ELECTRIC | ELECTRICAL_MAINTENANCE |
| LEAK, HVAC | FACILITY_MAINTENANCE |
| WATER_DISPENSER, FURNITURE | SHARED_EQUIPMENT |
| STUDENT_RECORD | ACADEMIC_ADMIN |
| UNKNOWN | AI가 준 값(허용 목록 안), 없으면 GENERAL_REVIEW |

- 예전 신고는 다시 분류하지 않는다. 화면에 보여줄 때 유형에서 업무 그룹을 계산하고, 대상·관련성은 비어 있다.
- 학교 관련성은 **기타(UNKNOWN) 신고에만** 쓰인다. 기존 유형의 장소 요구, 자동 배정, 접수 종류는 전과 같다.

## 3. 질문 규칙

- 새 물건이거나 유형을 정하지 못했다는 이유로는 질문하지 않는다. 문제와 장소가 있으면 바로 접수한다.
- 새 질문 사유는 `CAMPUS_RELEVANCE` 하나다: "학교 시설이나 학교에서 빌린 물건인가요, 개인 물건인가요?" 아래 조건이 모두 맞을 때 **한 번만** 묻는다.
  - 기타 유형이다
  - 대상은 있다(예: "연필이 부러졌어요")
  - 장소가 없다
  - 학교 물건인지 알 수 없다
- 질문 종류(`nextField`)는 `CATEGORY`다. 예전 프런트도 받은 값을 그대로 돌려보내므로 동작한다.
- "모르겠어요"라고 답하면 다시 묻지 않는다. 장소도 요구하지 않고 총괄 검토로 접수한다.
- 학교가 빌려준 물건(`SCHOOL_SERVICE`)과 개인 물건 문의는 장소를 요구하지 않는다.
- 유형이나 부서를 고르라고 묻지 않는다. 질문 횟수 제한, 같은 질문 반복 방지, 정정 병합, 긴급 즉시 접수는 그대로다.

## 4. 배정과 미배정 사유

- 업무 그룹 단위 자동 배정 규칙은 **만들지 않았다**. 확인된 개별 규칙을 그룹 전체로 넓히지 않기 위해서다. 기타 신고는 총괄이 기존 재배정 흐름으로 부서를 정한다.
- 개인 물건 문의와 학교 밖 요청은 문의(`requestKind=QUESTION`)로 저장하고, 시설 담당에게 자동으로 보내지 않는다.
- 학교 밖 요청(예: 개인 연필 추천)이면 접수 응답에 `scopeNotice` 안내 문구를 붙인다(선택 필드).
- `unassignedReason`에 기타 신고 사유 두 가지가 추가됐다. 기존 사유도 기타 신고에서 의미가 조금 달라졌다.

| 코드 | 화면 표시(제안) | 기타(UNKNOWN) 신고의 조건 |
|---|---|---|
| `GENERAL_INQUIRY` (신규) | 개인 물건 문의 | 학교 관련성이 개인 물건 |
| `OUT_OF_SCOPE` (신규) | 학교 처리 범위 밖 | 학교 관련성이 범위 밖 |
| `AI_UNCLASSIFIED` | AI 분류 불가 | 업무 그룹이 GENERAL_REVIEW (예전 기타 신고는 모두 여기) |
| `LOCATION_MISSING` | 장소 확인 필요 | 업무 그룹은 있으나 장소가 필요한데 없음 |
| `NO_RULE` | 배정 규칙 없음 | 업무 그룹은 알지만 자동 배정 규칙이 없음 |

## 5. 유사 후보

- 기존 유형(와이파이 등)은 바뀌지 않았다.
- 기타 신고끼리 비교할 때는 장소·기간 조건에 더해 업무 그룹이 같아야 후보가 된다.
  - Embedding 점수가 없을 때(RULE_ONLY): 양쪽 대상이 같고 양쪽 모두 증상이 있어야 한다. "같은 화장실에서 난 거울 파손"과 "같은 화장실의 휴지걸이 파손"은 후보가 아니다.
  - Embedding 점수가 있을 때: 기존 임계값(0.82)을 그대로 쓴다. 양쪽 대상이 모두 있는데 서로 다르면 제외한다.
- 후보는 지금처럼 관리자 판단을 기다리는 제안일 뿐이며, 자동으로 사건에 연결하지 않는다. Embedding 입력 문장은 그대로라 저장된 벡터를 다시 쓸 수 있다.
- 평가용 설명(`evaluate`)에 `workGroupTargetMatch` 값과 제외 사유 `WORK_GROUP_TARGET`이 추가됐다.

## 6. AI

- 프롬프트 `hybrid-intake-v6`, 정책 `hybrid-check-v7`. 응답 스키마에 세 필드가 추가됐고 strict 스키마라 매번 채워진다.
- 새 필드가 없는 예전 응답도 그대로 받는다. 저장된 실제 응답 재생 테스트가 이 경우다.
- AI가 허용 목록 밖의 값을 보내면 응답 전체를 거부한다. 부서 이름 필드를 보내거나 대상이 100자를 넘어도 마찬가지다.
- 실제 LLM의 개발용 스모크 5건은 아래 기록과 같다. 일반적인 품질이나 모든 물건에 대한 정확도가 검증된 것은 아니다.
- DEMO 분류기는 학교 단어·장소·"빌린"·"두고 왔"·"제 거예요"·"추천해" 같은 표현으로 관련성을 정한다. 시연용 규칙이며 일반 분류기가 아니다.

## 7. 검토 후 보완한 범위

- 기존 4개 추가 답변 업데이트에 `TARGET`, `CAMPUS_RELEVANCE`를 추가했다. 이는 AI 응답 내부의 갱신 근거이며, 학생 화면의 질문 종류나 신고 저장 API에 필수 항목을 추가한 것이 아니다. 예전 4개 그룹 응답·캐시는 계속 허용한다.
- 소유 구분만 명시적으로 정정해도 반영하고, 개인 물건으로 바뀌면 시설 업무 그룹을 남기지 않는다. 장소·시간만 답하거나 증상만 보완한 경우 기존 소유·대상을 보존한다. 문자열 근거가 최신 답변에 없으면 새 필드 갱신을 적용하지 않는다.
- 명시적으로 부정한 대상의 대체 물건이 불명확하면 이전 대상을 지우고 이전 대상의 근거도 재사용하지 않는다. 실제 점검 대상이 필요한 경우 제한된 기존 추가 질문으로 보완한다. 모호한 소유 정정은 `UNCERTAIN`으로 남긴다.
- `targetText`는 AI가 일반적인 한국어 명칭으로 정리한다. 기존 저장값 호환은 확인된 `미러`/`mirror` → `거울`만 제한적으로 보정한다. 물건별 유형·부서 목록을 늘리지 않는다. 미등록 동의어는 여전히 놓칠 수 있다. 서로 다른 대상을 높은 문장 전체 유사도만으로 연결하지 않는다.
- 유사도 임계값 0.82, 와이파이 보완 임계값 0.70, Embedding 입력 및 관리자 승인 조건은 변경하지 않았다. 새 DB 마이그레이션은 없으며 팀원 변경분 V10을 그대로 사용한다.
