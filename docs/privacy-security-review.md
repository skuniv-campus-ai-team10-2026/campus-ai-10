# 로컬 실험의 접근·개인정보 보관 검토

확인일: 2026-10-11 KST. 현재 코드와 로컬 실행에 대한 기술 검토다. 운영 정책 승인이나 법률 준수 판정은 아니다. 실제 학생 데이터는 입력하지 않았고 학교 시스템에 접수하지 않았다.

## 저장·전송 범위

| 위치 | 데이터 | 현재 보관/삭제 동작 |
|---|---|---|
| users | 실험 아이디·표시 이름·BCrypt 해시·역할·활성 상태 | 자동 만료·삭제 없음, 학교 SSO 없음 |
| reports | 학생 ID·신고 원문·장소·증상·발생일·처리 결과·임베딩 | 자동 보관 기간/삭제 작업 없음. 임베딩도 익명 데이터라고 가정하지 않음 |
| 이력·사건·유사쌍 | 처리자·시각·상태 변경·검토 결정·참조 관계 | 감사 증거로 유지, 보관 기간과 삭제 정책 미결정 |
| 브라우저 sessionStorage | 작성 중 원문/분석 초안·마지막 접수 ID | 접수 성공·로그아웃·세션 만료·새 로그인 시 해당 값 제거. 탭 내 임시 보존 |
| 서버 세션 | 인증 정보·CSRF | 30분 inactivity timeout, 로그아웃·계정 비활성/역할 변경 시 무효화 |
| `.runtime` | DB·데모 비밀번호·API 키 설정·검증 로그·TLS 개인키 | 로컬 파일, Git 제외. `.gitignore`는 OS 접근 통제나 암호화가 아님 |
| 외부 AI | LIVE의 텍스트/추가 답변/구조화 내용·임베딩 입력 | 합성 입력으로 분석30회·임베딩40회 전송 성공. 실제 학생 데이터 없음. 공급자 정책 별도 적용 |

자동 개인정보 마스킹·보존기간 삭제·삭제 요청 API·암호화 백업을 구현했다고 주장하지 않는다. AI에 사용자 ID나 비밀번호를 직접 첨부하지 않아도 원문에 사용자가 쓴 개인정보는 포함될 수 있다.

## 확인한 방어와 실행 증거

- 실제 MySQL HTTP 회귀에서 역할·소유권·CSRF·세션 회수와 사건/상태 충돌 방지를 검증했다.
- 로컬 프록시 경유 12개 검증에서 경로 탈출 차단, Host/Origin 제한, 본문 상한, 세션 ID 교체, SQL injection 문자열의 로그인 거절, 서버 소유 필드 무시, 로그아웃, 중복 UUID 8개 중 1건 저장, 동시 처리 시작 2개 중 1건 성공을 확인했다. [원시 결과](evaluation/production-http-results.json)
- 쿠키의 Secure/HttpOnly/SameSite 속성은 확인했다. HTTP 클라이언트가 쿠키를 직접 전달했으므로 HTTPS 브라우저 전송 동작까지 검증한 것은 아니다. [TLS 환경 장애](deployment-verification.md)
- 원문은 React 텍스트 노드로 렌더링하며 `dangerouslySetInnerHTML`을 사용하지 않는 것을 소스로 확인했다. HTML 모양 입력의 JSON 저장/조회도 시험했다. 모든 브라우저 XSS 경로의 침투 테스트는 아니다.
- 세션 만료 후 이전 사용자 초안이 남던 문제를 수정했다. 초기 인증 401·실행 중 만료·새 로그인 시 앱 초안을 제거하며 무관한 저장 키는 유지한다. 새 회귀 2개를 포함한 프런트 테스트 12/12 및 빌드가 통과했다.
- 소스·문서·스크립트·정적 번들 76개 텍스트 파일에서 현재 로컬 DB/데모 비밀번호의 정확한 값과 API 키 형태를 검사해 일치 0개를 확인했다. 비밀 전체를 보증하는 전수 보안 감사는 아니다.

## 운영 전 결정할 사항

| 항목 | 현재 상태 | 필요한 결정 |
|---|---|---|
| 접근 | 모든 ADMIN이 전체 신고 조회 가능 | 관리자 발급·회수 담당자, 최소 권한과 학교 인증 연결 여부 |
| 로그인 남용 | 별도 rate limit·잠금·MFA 없음 | 배포 프록시/인증 계층의 제한과 복구 정책 |
| 보관 | DB 자동 삭제 없음 | 원문·결과·이력·임베딩별 기간 및 삭제/익명화 기준 |
| 로그·백업 | 로컬 개발 로그, 백업/복구 운영 검증 없음 | 로그 마스킹/접근 권한/기간, 백업 암호화·복구 훈련 |
| AI 외부 전송 | 합성 입력으로 70회 호출 검증, 실제 학생 데이터 미전송 | 실제 개인정보 전송 범위·안내·위탁/국외 처리 검토 책임자 |
| HTTPS | 로컬 백신 인증서 교체로 차단 | 신뢰 가능한 배포 환경의 도메인·인증서·갱신·Secure 쿠키 재검증 |

실험 단계에서는 합성 데이터만 유지하고, 실험 종료 시 데이터 삭제 여부를 소유자가 결정하도록 한다. 임의의 법정 보존기간을 만들어 적용하거나 기존 시연 데이터를 자동 삭제하지 않았다.

OpenAI의 `store=false`는 완전한 무보관 설정이 아니다. 기본 악용 방지 로그 보관과 예외, 모델별 캐시 조건이 있으며 계정의 Zero Data Retention 승인 여부도 별도다. [공식 데이터 제어](https://developers.openai.com/api/docs/guides/your-data)
