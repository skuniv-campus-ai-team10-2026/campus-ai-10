# PR #4 수정 검증 (2026-10-25)

- 추가 질문 중에도 내용 직접 수정과 관리자 검토 접수 버튼을 표시한다. 추가 답변 없이 같은 요청 식별자로 검토 접수하며, 실패 시 기존 원문과 작성 상태를 보존한다.
- 사진 업로드의 네트워크 오류, 타임아웃, 5xx, 알 수 없는 오류는 저장 여부 불확실 상태로 다룬다. 첨부 목록을 다시 조회하고 재전송을 차단한다. 확실한 거부 응답(예: 잘못된 이미지 400)은 사용자가 실패한 파일만 다시 시도할 수 있다.
- 업로드 큐·잠금·오류·시도 여부를 신고별 메모리 상태로 공유한다. 화면 이동, 재진입, StrictMode에서 같은 파일을 동시에 전송하거나 실패한 요청을 자동 재시도하지 않는다. 세션 종료 시 남은 큐를 중단한다.
- 첨부 실패는 신고 재접수를 호출하지 않는다. 서버의 원문 보존 및 같은 접수 요청 재시도 시 신고 1건 유지도 HTTP 통합 테스트로 검증했다.

현재 첨부 목록 API에는 파일 식별자나 업로드 요청 토큰이 없다. 따라서 조회 결과가 비어 있어도 응답을 잃은 파일의 저장 여부를 확정할 수 없다. 불확실 상태는 같은 세션에서 유지하며, 목록 새로 조회만 허용한다. 새로고침 시 메모리의 파일 큐는 사라지고 자동 재전송하지 않는다.
